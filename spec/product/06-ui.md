# UI

## UI Type

Web dashboard — server-rendered HTML via FastAPI + Jinja2. No JS build step. All interactivity is vanilla JS in the template files.

## Tech Stack

Python 3.12 + FastAPI + Jinja2 + plain HTML/CSS/JS (no frontend framework, no bundler).

---

## Layout

Two-panel app shell rendered by `base.html` + `index.html`:

```
┌─────────────────────────────────────────────────────┐
│  Header: "Data Analysis Agent"      [Project notes]  │
├──────────────┬──────────────────────────────────────┤
│  Sidebar     │  Main                                 │
│              │  ┌──────────────┬──────────────────┐  │
│  Sessions    │  │  Datasets    │  Upload           │  │
│  list        │  └──────────────┴──────────────────┘  │
│              │  ┌────────────────────────────────┐   │
│  ──────────  │  │  Conversation thread + query   │   │
│  Token       │  └────────────────────────────────┘   │
│  usage       │                                       │
└──────────────┴──────────────────────────────────────┘
```

### Responsive breakpoints

- `≤ 960 px`: sidebar stacks above main, both full-width
- `≤ 640 px`: datasets and upload cards stack vertically; sidebar sub-panels stack

## Components

### Header (`base.html`)

- App name + tagline
- **Project notes** button — opens the persistent memory modal (`memory-modal`)
- Stub mode banner (yellow, below header) shown when `llm_provider == "stub"`:
  `⚠ Running in stub mode — set DATA_ANALYST_GEMINI_API_KEY in your .env for real answers`

### Sidebar — Sessions panel

- List of past sessions (name or first question, turn count, relative timestamp)
- Per-session: checkbox (bulk select), click body to resume, ✏ rename inline (Enter to save, Escape to cancel)
- **Delete selected** button — appears when ≥ 1 checkbox checked; opens confirmation modal
- **+ New** button — clears thread, deselects active session
- **Clear all sessions** button (footer, danger style) — opens confirmation modal

### Sidebar — Token usage widget

- Model name (uppercased via CSS)
- Two columns: **Last query** (tokens In/Out, Cost for the most recent run) | **Today** (In/Out, Queries, Cost)
- Storage row: dataset count + total rows across all datasets
- Last-query stats reflect the single most recent run; daily stats fetched from `GET /stats/daily`
- Cost is computed client-side from a built-in pricing table; shows "N/A" for unknown models

### Datasets card ("Tables")

- Card title is **Tables**
- Scrollable list of all datasets (uploaded and derived) (max-height 200 px)
- **Filter tabs** in card header: **All** | **Uploaded** | **Derived** | **This session** — "This session" filters by cross-referencing `derived_from_run_id` against the run IDs in `GET /sessions/{currentSessionId}` turns; tab is hidden when no session is active
- Per dataset row: checkbox, filename + dimensions (rows × cols), **▸ cols** toggle, 🧹 clean button (uploaded only), 🗑 delete button
  - Derived datasets show a **Derived** badge (small pill, green) after the filename
  - Stale derived datasets show an **⚠ Stale** badge (amber) when any parent was updated after derivation
- **▸ cols** expands a chip list of column names; for derived datasets also shows: "Derived from: [parent filenames]" and the `derivation_description`
- **Re-derive** button appears on stale derived dataset rows — calls `POST /datasets/{id}/re-derive`; replaces the ⚠ Stale badge with a spinner, then removes the badge on success; on success also refreshes the datasets list
- After a query completes (`status` transitions to `completed`), the datasets card re-fetches `GET /datasets` to surface any derived datasets that `save_dataset()` created during the run
- Inline delete confirm: hides the dataset row's content, shows "Delete? / Cancel" — no `confirm()` dialog; if the dataset has derived children, the confirm text includes "and N derived dataset(s)"
- Bulk actions: **Select all / Deselect all**, **Delete selected** (custom modal), **Clear all** (custom modal)
- No per-dataset notes panel here — dataset context notes are edited in the Database tab's **Table Description** pane (see below)

### Upload card

- Drag-and-drop zone (accepts files and folders)
- Folder drop: reads `_notes.txt` / `context.txt` / `readme.txt` etc. as folder-level notes; matches `<stem>.notes.txt` files per data file
- **Choose files** button → hidden `<input type="file">` (`.csv .tsv .txt .json .xlsx .xls`)
- **Staged file list**: files wait in a client-side `Map` before upload — user can rename, add typed notes, attach a `.txt`/`.md` notes file, or remove
- **Upload N file(s)** button — uploads up to 3 files concurrently; per-file queue row shows ⏳/✓/✗ and inline "Use existing / Upload anyway" on 409 duplicate

### Conversation card

- **Thread** (`role="log"`, `aria-live="polite"`) — appended turns, smooth scroll to new turn
- Per turn: question in blue, timestamp + elapsed time, optional **⚠ Best effort** badge, rendered Markdown answer (tables, bold, bullets, code, headings), iteration count + token counts, **Datasets used** detail disclosure, **Steps inspector**
- **Clarification turns** (C26): when `/ask` returns `clarification_needed: true`, `appendClarification(clarification_question)` appends a distinct turn:
  - Amber left border; header label **"Needs clarification"** (small muted text); body is the clarification question text
  - No iteration count, no token stats, no Steps inspector, no "Datasets used" disclosure, no "Best effort" badge, no Export MD button
  - The original question string is stored in `_pendingQuestion`
  - Textarea and Ask button remain active; user types their answer and submits normally
  - Next `/ask` sends `{question: <user_answer>, session_id: <current>}` — session history carries context for the agent; no special field required
  - On session resume (`GET /sessions/{id}`): turns with `status="clarification"` render with this same style; the `answer` field contains the clarification question text
- **Steps inspector**: collapsible toggle showing each agent iteration — code block (dark theme) + result/error block; **Copy** button per step; error steps show a red "✕ Error" badge
- **Follow-up chips**: 2–3 clickable question suggestions appended after each answer
- **Export MD** button — downloads conversation as a `.md` file
- **Question textarea** — Enter to submit (Shift+Enter for newline)
- **Ask** button — disabled while running, shows spinner
- **Stop** button — shown while a query is running; calls `AbortController.abort()` to cancel the fetch
- **Progress row** — shown while running: elapsed timer, iteration progress bar (`Step N / M`), reads from `GET /runs/current`. During the C26 pre-flight clarification check (before the ReAct loop starts), the progress row shows "Checking…" with the elapsed timer only — no iteration counter, since no agent iterations have occurred yet

### Database tab

A separate tab providing a session-scoped view of the active session's data universe: every dataset in play, its schema, and how datasets relate to each other.

**Navigation:** Tab bar at the top of the main area: `[Analyse]` (default) `[Database]`. `switchTab(name)` toggles visibility; switching to Database calls `loadDatabaseTab()`.

**Session scope:**

| State | Datasets shown |
| ----- | -------------- |
| Session active (`currentSessionId` set) | Uploaded datasets in `session.dataset_ids` + derived datasets whose `derived_from_run_id` is in the session's run IDs (computed from `GET /sessions/{id}` turns) |
| No session active | All uploaded datasets; no derived datasets |

When no session is active a banner reads: *"No active session — showing available uploads. Start a conversation to create derived datasets."*

**Header bar:**

- Session name in bold (or "No active session" in muted text)
- Subtitle: `N uploaded · M derived` (derived count hidden when 0)
- **Clear database** button (danger style, right-aligned) — opens `clear-db-modal`; on confirm calls `DELETE /datasets`, clears `_dbDatasets`, re-renders empty graph and strip, shows empty state banner

**Schema — ER diagram (`#lineage-svg`):**

Rendered by `renderERDiagram(datasets)`. A full entity-relationship diagram (not a topological lineage DAG). Each dataset is drawn as a **table card** listing its columns; foreign-key relationships between tables are inferred and drawn as crow's-foot connectors.

The panel header reads **Schema** and carries a legend: card swatches for **uploaded** (blue) / **derived** (green), and dtype color dots for **number** (blue), **text** (purple), **date** (amber), **other** (grey).

*Table cards:*

| Element | Spec |
| ------- | ---- |
| Card | Rounded rect with drop shadow; header bar = table name (filename minus extension, truncated ~24 chars); uploaded = blue header / grey border, derived = green header / green border + small "derived" tag |
| Active card | Currently-selected dataset gets a 2 px blue border |
| Column rows | One row per column (first 8 shown; a "+ N more" row caps the rest), zebra striped. Each row shows the column name plus a **dtype color dot** at the right (number = blue, text = purple, date = amber, boolean = green, other = grey). No dtype text — the dot encodes type. |
| Empty state | Centered text *"No datasets in this scope"* when the scope is empty |

*Foreign-key inference (`_erFkLinks`)* — the single source of truth for both the diagram edges and the right-panel PK/FK badges, so the two can never disagree. It links uploaded tables on shared keys:

- Columns ending in `_id` shared by ≥2 tables (matched by exact name).
- The **zip-code-prefix family**: `customer_zip_code_prefix` / `seller_zip_code_prefix` / `geolocation_zip_code_prefix` are normalized to one logical key (`zip_code_prefix`), with **geolocation** as the canonical hub.
- **Exact-name shared specific columns** (non-`_id`), e.g. `product_category_name` → `product_category_name_translation`.
- A **denylist** of generic columns (`id`, `name`, `date`, `value`, `type`, `status`, `city`, `state`, `description`, `price`, `category`, `code`, `created_at`, … ) is excluded so unrelated tables aren't joined.
- The PK-owning **canonical** table for a key is chosen by filename: full-key match first (`product_category_name` → the `*_translation` file's counterpart), else the entity noun (`order_id` → "order" → `olist_orders_*`; zip → "geolocation"). The canonical side is the "one" (PK); every other table sharing the key is a "many" (FK).

*Edges (column-anchored, obstacle-dodging):*

| Element | Spec |
| ------- | ---- |
| FK edge | Leaves the **exact FK column row** of the child card and enters the **key column row** of the parent card — column-anchored, not card-center. Drawn as a rounded orthogonal (right-angle) elbow connector whose vertical run is **routed around** any cards it would otherwise cross (`dodgeX`). |
| Cardinality marks | "many"/child (FK) end has a **crow's-foot**; "one"/parent (PK) end has a **single tick**. |
| Derived edge | Dashed green arrow from parent dataset to its derived child (anchored at card centers), drawn from `derived_from_dataset_ids`. |
| Join-key label | A dark pill showing the join key, positioned on the edge's vertical channel. **Hover-only** — hidden by default, revealed when the connected table is hovered. |

*Layout:* force-directed (repulsion + pull-only springs, with cooling) → overlap-resolution pass that guarantees no two cards intersect → an **aspect-aware horizontal x-stretch** that widens a too-tall layout to fill the wide Schema pane → normalize + auto-fit/center to the viewport.

*Interaction:*

| Element | Spec |
| ------- | ---- |
| Controls | **[Fit]** — re-fits/centers the diagram; **[+]** / **[–]** zoom buttons; drag to **pan**; **wheel to zoom** (clamped 0.5×–3×) |
| Click card | Calls `selectDataset(id)` — marks the card active (blue border), populates the Table Description panel, marks the matching strip chip active |
| Hover card | **Highlights its relationships**: connected edges turn blue/bold, the join-key label on each appears, the hovered card and its connected tables stay fully lit, all other cards dim to ~0.3 opacity. Leaving the card restores everything. |

---

**Table Description panel (`#db-schema-panel`):**

Titled **Table Description**. Populated when `selectDataset(id)` is called. Fetches `GET /datasets/{id}` on first selection; result cached in `_dbSchemaCache`.

*Empty state* (nothing selected): *"← Click a table to see its description."*

*When a dataset is selected:*

- **Header row:** filename (bold), origin badge (**uploaded** blue / **derived** green), **stale** amber badge when `stale: true`
- **Meta row:** `{rows} rows × {cols} cols · {FORMAT}` (format uppercased, e.g. CSV)
- **Derived-only block:**
  - "Derived from:" followed by each parent filename as a clickable chip — click calls `selectDataset(parent_id)`
  - Collapsible **"Derivation code ▸"** — dark-theme `<pre>` block containing `derivation_code`
- **Keys block** (shown when any key is inferred): a **PK** row and/or **FK** row listing the inferred primary- and foreign-key column names. Inference comes from the same `_erFkLinks` used by the diagram (plus a local rule that badges a table's own filename-matching `*_id` as its PK even when nothing references it).
- **Columns table:** two columns — **Name** | **Type** — one row per entry in `columns_schema`; the Name cell carries a **PK** (blue) or **FK** (green) badge for inferred key columns; fixed-height scrollable (`max-height: 260px`)
- **Context notes:** `<textarea>` showing `context`; auto-saves on blur via `PATCH /datasets/{id}/context`; placeholder "Notes about this dataset…". A **Generate notes** button calls `POST /datasets/{id}/describe` and polls `GET /datasets/{id}` (showing a "Generating…" spinner) until `auto_notes_status` clears, then fills the textarea with the LLM-generated notes.
- **Data preview:** fetches `GET /datasets/{id}/preview` (cached per dataset in `_dbPreviewCache`) and renders the first ~10 rows in a scrollable table — integers/floats are locale-formatted, `null`/missing values render as a muted "null". Shows "Preview unavailable: …" on error.
- **Actions:**
  - 🧹 **Clean** (uploaded only) — opens `clean-modal` pre-populated with this dataset's ID
  - 🔄 **Re-derive** (derived only) — calls `POST /datasets/{id}/re-derive`; button shows spinner during request; on success: updates the entry in `_dbDatasets`, re-renders the diagram (removes stale border), refreshes the panel with new row/col counts and `stale: false`
  - 🗑 **Delete** — inline confirm; on confirm: calls `DELETE /datasets/{id}`, removes from `_dbDatasets`, re-renders the diagram and strip, clears the panel

---

**Dataset strip (`#db-strip`):**

Horizontal scrollable row at the bottom of the Database tab. One chip per session dataset.

- Chip content: type icon (📄 uploaded / 🧩 derived) + filename (truncated ~20 chars) + **⚠** if stale
- Order: uploaded datasets first, then derived (by `created_at` ascending)
- Click chip → `selectDataset(id)` (same as clicking the table card)
- Active chip (currently selected) has a highlighted border
- Strip re-renders whenever `_dbDatasets` changes (after delete, re-derive, or query completion)

### Modals

All modals use `.modal-overlay` class. Backdrop click and Escape key close any open modal. First focusable element receives focus on open.

| Modal ID | Trigger | Purpose |
|---|---|---|
| `memory-modal` | Header **Project notes** button | Edit persistent project notes injected into every query |
| `clean-modal` | 🧹 per dataset (Analyse card or Database Table Description pane) | NL data cleaning: describe operation → preview code + row counts → apply |
| `clear-sessions-modal` | "Clear all sessions" | Confirm bulk session delete (all sessions) |
| `del-sel-sessions-modal` | "Delete sel." in sessions | Confirm delete of checked sessions |
| `clear-all-datasets-modal` | "Clear all" in datasets card | Confirm delete all datasets + sessions |
| `del-sel-modal` | "Delete selected" in datasets card | Confirm delete of checked datasets |
| `clear-db-modal` | "Clear database" in Database tab header | Confirm deletion of ALL datasets (cascades to all sessions, runs, and derived datasets) via `DELETE /datasets`; navigates to empty state on success |

## Error States

| Situation | Feedback |
|---|---|
| Upload failure | ✗ icon in queue row + error text inline |
| Duplicate file (409) | ⚠ in queue row + "Use existing / Upload anyway" buttons |
| Ask failure | Red error message in `#ask-status` |
| Query cancelled | Amber "Query cancelled." message |
| Agent best-effort | Yellow **⚠ Best effort** badge on the turn |
| Dataset delete failure | Inline error row with Dismiss button |

## Key JS Globals

| Symbol | Purpose |
|---|---|
| `esc(s)` | HTML-escape (`&`, `<`, `>`, `"`, `'`) |
| `openModal(id)` / `closeModal(id)` | Modal open/close with focus management |
| `announce(msg)` | Writes to `#aria-live` for screen readers |
| `tuAddRun(ti, to)` | Accumulates token counts in sessionStorage |
| `_askController` | `AbortController` instance for the current query fetch |
| `_staged` | `Map` of staged file entries before upload |
| `currentSessionId` | UUID of the active session, or `null` |
| `appendClarification(q)` | Appends a clarification turn to the thread; stores original question in `_pendingQuestion` |
| `_pendingQuestion` | Original question string held while clarification is outstanding; cleared after follow-up is submitted |
| `switchTab(name)` | Toggles between `'analyse'` and `'database'`; calls `loadDatabaseTab()` when switching to Database |
| `loadDatabaseTab()` | Fetches `GET /sessions/{id}` + `GET /datasets`, computes session-scoped subset, batch-fetches schemas, stores in `_dbDatasets`, renders the ER diagram and strip |
| `renderERDiagram(datasets)` | Builds and renders the SVG ER diagram into `#lineage-svg`: table cards + inferred FK crow's-foot edges; force-directed layout with overlap resolution, x-stretch, and auto-fit; hover-to-highlight relationships |
| `_erFkLinks(datasets)` | Inferred FK links among uploaded tables (`{from, to, key, fromCol, toCol}`); the single source of truth for BOTH the diagram edges and the right-panel PK/FK badges |
| `selectDataset(id)` | Marks the table card + strip chip active, fetches `GET /datasets/{id}` if not in `_dbSchemaCache`, populates the Table Description panel, triggers the data-preview fetch |
| `_dbDatasets` | Array of current session's dataset objects (refreshed by `loadDatabaseTab()`) |
| `_dbSchemaCache` | `Map<dataset_id, dataset>` — avoids redundant `GET /datasets/{id}` fetches within a tab session |
| `_dbPreviewCache` | `Map<dataset_id, preview>` — caches `GET /datasets/{id}/preview` results |

## Accessibility

- `role="log"` + `aria-live="polite"` on the conversation thread
- `role="list"` / `role="listitem"` on session and dataset lists
- `aria-label` on all icon-only buttons
- `aria-modal="true"` + `aria-labelledby` on all modals
- `role="progressbar"` with `aria-valuenow` on the iteration bar
- `aria-live="polite"` on `#ask-status` and `#progress-row`
- `#aria-live` hidden live region for programmatic `announce()` calls
- `type="button"` on all non-submit buttons
