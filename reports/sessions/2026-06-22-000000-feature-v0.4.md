#### C31 compression robustness (the "chain thing")
Audited all compression trigger/consumption paths directly. **Finding: the C30→C31 chain already existed** (since commit `67126ad`) — `generate_dataset_notes` Step 5 already compresses, and every write path triggers compression correctly. The earlier session-report claim that the chain was missing was wrong. The real gaps were elsewhere:

1. **No self-heal for uncompressed/failed rows (HIGH)** — datasets with notes set pre-C31, or whose compression failed once, had `context_facts=NULL` forever → full raw notes injected every query.
2. **Silent permanent failure** — `extract_facts` returns `[]` on any LLM hiccup; both compressors swallow errors with no retry.
3. **Stale facts on edit (correctness)** — `update_context`/`update_memory` didn't clear old facts before recompression → builder served facts describing the previous text.

**Fix (lazy on-read self-heal, user-chosen):**
- `compress.py`: in-flight guard (`_inflight` set + lock) prevents duplicate concurrent compression; `compress_dataset_context_async` / `compress_memory_async` fire-and-forget helpers.
- `nodes.py` `setup()` + `_build_prompt()`: when a source has raw text but no facts, fire background compression and use raw text this turn; facts ready next turn. Self-heals all existing data without a backfill or restart.
- `datasets.py` / `memory.py`: clear `*_facts` to NULL on write so the recompression window serves fresh raw text, not stale facts.
- Tests: `test_lazy_self_heal_compresses_uncompressed_notes`, `test_context_patch_clears_stale_facts`. Full suite: 112 passed.
- Spec `13-semantic-compression.md` updated (lazy self-heal, concurrency guard, clear-on-write).
